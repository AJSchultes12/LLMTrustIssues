# Enron August 2001 Experiment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build everything downstream of the existing data scripts: case entries, disguise, prompts, model runner with spend caps, recall probe, leakage scan, and scoring, for Enron decision points EN-3a and EN-3b.

**Architecture:** A new `llmtrust/` package of small modules with plain dataclasses between them. Sources are loaded per decision point with hard cutoff guards, disguised at level 1, 2 or 3, rendered into a prompt, sent to a model arm through one client interface, and logged as one JSON record per trial. Probe, leak scan and scoring read those records.

**Tech Stack:** Python 3.10+, `requests` and `PyYAML` (already used), `pytest`, the `anthropic` SDK for Claude, and an OpenAI-compatible HTTP client (plain `requests`) for Ollama, OpenRouter, Groq, Gemini's compatible endpoint, and RunPod/vLLM.

**Spec:** `docs/superpowers/specs/2026-11-06-enron-august-2001-design.md`

## Global Constraints

- Every source must be dated strictly before the decision point's `cutoff`. The scenario brief is the one exception.
- Nothing listed under `evaluation_only` ever enters a prompt.
- The scoring rubric is committed before any model run.
- Three disguise levels: 1 named, 2 names stripped, 3 fingerprints removed (one scale factor for dollar figures, one year shift for dates, structures renamed). The factor and shift are fixed per case and recorded in each trial.
- Watkins memo is rewritten at levels 2 and 3: wording changes, substance does not.
- Temperature 0 where the API allows it. Log exact model ID, provider, date and the full prompt for every trial.
- Spend caps: $20 for non-Claude arms and $8 for the Claude arm, tracked separately. The runner estimates before each batch and stops at the cap. Local compute is a laptop with a 4GB GPU.
- SEC requests need a User-Agent with the user's own contact info (`SEC_USER_AGENT`); the user sets it, the code never fills it in.
- Enron emails are real people's messages: research use only, evidence not fact.
- Rubric criteria score against documented facts, never "the executives lied".

## Review Focus

Input classes the spec implies but no obvious task covers. Each line has a test in the owning task.

1. Names inside other words and possessives: "Lay" in "relay", "Enron's", "ENRON CORP/OR/" (Task 5).
2. Numeric and short dates and fiscal labels: "6/28/99", "FY2001", "Q2 2001", "'01" (Task 5).
3. Option-order bias: the same options always listed in the same order (Task 7).
4. Model replies that are not valid JSON, name a letter that does not exist, or refuse (Task 9).
5. Context truncation that silently drops the memo or the scenario brief (Task 4).

## Shared types (`llmtrust/types.py`, created in Task 1)

```python
@dataclass(frozen=True)
class DecisionPoint:
    id: str; title: str; decision_date: str; cutoff: str
    options: list[str]; actual_decision: str
    edgar_forms: list[str]; email_custodians: list[str]
    role: str; scenario_brief: str; stake_statement: str

@dataclass(frozen=True)
class Case:
    case_id: str; company: str
    decision_points: list[DecisionPoint]
    evaluation_only: list[dict]       # {"description": str, "url": str | None}
    leakage_terms: list[str]

@dataclass(frozen=True)
class SourceDoc:
    date: str                         # ISO date
    kind: str                         # "filing" | "email" | "document"
    title: str
    text: str

@dataclass(frozen=True)
class Prompt:
    system: str; user: str
    option_map: dict[str, str]        # letter -> original option text

@dataclass(frozen=True)
class TrialSpec:
    case_id: str; decision_id: str; level: int; stake: bool
    scenario: str                     # "real" | "twin"
    arm: str; repeat: int
    @property
    def trial_id(self) -> str: ...    # e.g. "enron.EN-3b.L3.stake.twin.claude-haiku.r2"

@dataclass(frozen=True)
class Completion:
    text: str; model_id: str; provider: str
    input_tokens: int; output_tokens: int; finished_at: str
```
